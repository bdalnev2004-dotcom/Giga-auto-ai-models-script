# Развёртывание на сервере

> **Код ни разу не запускался.** Он написан и вычитан, но ни одна строка не исполнялась —
> в среде разработки не было ни Python, ни ключей. Первый запуск, скорее всего, вскроет
> ошибки. Разворачивай как тестовый прогон, а не как готовый прод.

## Что нужно на сервере

- Любой VPS с Docker и Docker Compose. 2 ГБ RAM хватает с запасом.
- Открытых портов **не нужно** — бот работает на long polling, только исходящий трафик.
- Postgres и Redis поднимает сам compose, ставить отдельно не надо.

## Порядок

### 1. Залить код

```bash
git clone https://github.com/bdalnev2004-dotcom/Giga-auto-ai-models-script.git giga-bot
cd giga-bot
```

### 2. Сгенерировать ключ шифрования

Понадобится для `.env`. Если Python на сервере нет, можно прямо в Docker:

```bash
docker run --rm python:3.12-slim sh -c "pip install -q cryptography && python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'"
```

Сохрани результат. **Потеряешь этот ключ — потеряешь все сохранённые пароли аккаунтов**,
расшифровать их будет нечем.

### 3. Заполнить .env

```bash
cp .env.example .env
nano .env
```

Минимум для старта — без этих пяти бот не поднимется, `config.py` требует их при импорте:

| Переменная | Откуда |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys |
| `POSTGRES_PASSWORD` | придумываешь сам |
| `DATABASE_URL` | подставить туда же этот пароль |
| `VAULT_ENCRYPTION_KEY` | из шага 2 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | путь к JSON, шаг 4 |

Внимание на адреса: внутри compose хосты — `postgres` и `redis`, **не** `localhost`.
В `.env.example` уже проставлено правильно.

### 4. Положить ключ Google Drive

```bash
mkdir -p secrets
# скопировать сюда JSON сервис-аккаунта
mv ~/drive-service-account.json secrets/
chmod 600 secrets/drive-service-account.json
```

Сервис-аккаунт заводится в Google Cloud Console → Service Accounts, там же ключ в формате
JSON. Не забудь **включить Drive API** и **расшарить корневую папку** фермы на email
сервис-аккаунта — иначе он её не увидит.

Если Drive пока не настроен — бот всё равно стартует, но при создании аккаунта скажет,
что папки создать не удалось.

### 5. Запустить

```bash
docker compose up -d --build
```

Первая сборка идёт несколько минут: ставится ffmpeg и зависимости.

### 6. Проверить

```bash
docker compose logs -f bot
```

Ожидаемое при успехе — строки aiogram о старте polling. Если контейнер перезапускается
по кругу, смотри первую ошибку в логе: почти всегда это незаполненная переменная в `.env`.

Проверка ключей и сервисов одной командой:

```bash
docker compose exec bot python scripts/healthcheck.py
```

Незаполненный ключ покажет `SKIP`, а не ошибку — запускать можно на любой стадии настройки.

### 7. Первый диалог

Напиши боту в Telegram `создать блогершу` — пойдёт интервью из 15 вопросов, в конце
соберётся карточка персонажа и создастся аккаунт. Потом `bio` или `сценарии` — проверишь
генерацию вариантов.

## Обновление

```bash
git pull
docker compose up -d --build
```

## Что может сломаться на первом запуске

- **Контейнер падает сразу** — не заполнена одна из пяти обязательных переменных.
  Точное имя будет в трейсбеке `KeyError`.
- **Не подключается база** — пароль в `DATABASE_URL` не совпал с `POSTGRES_PASSWORD`.
- **Ошибки Google Drive** — не включён Drive API или папка не расшарена на сервис-аккаунт.
- **Ошибка при генерации** — не выверенные вживую промпты либо неверный формат ответа.
  Логи покажут текст исключения из `claude_service`.

## Чего в системе пока нет

Публикация **не замкнута**: аппрув отрабатывает, но реального вызова постинга из
`approvals.py` нет. Монтаж и генерация изображений — заглушки. Подробности и текущие
приоритеты — в [CLAUDE.md](CLAUDE.md).
