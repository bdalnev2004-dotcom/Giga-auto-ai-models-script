## Что это

Ферма ~20 Instagram-аккаунтов (AI-инфлюенсеры + бренды) под управлением Telegram-бота.
Генерация контента через AI, утверждение одной цифрой в чате, автопубликация Reels.

**Путь одной единицы контента:**
триггер в чате → контекст аккаунта → уточняющие вопросы → генерация → Google Drive
(нумерованные варианты) → аппрув номером/✅/❌ → публикация → аудит-лог.

## Ключевые договорённости (не переигрывать без спроса)

- **Постинг — только Instagram Reels, через `instagrapi`.** HikerAPI **не умеет публиковать**,
  это read-only API; ключ от него оставлен только для чтения/аналитики. Проверено по докам.
- **Vyra не годится для автоматизации.** Проверено по докам: авторизация только через
  OAuth в браузере (API-ключа нет), и нужен живой браузер с открытым проектом в редакторе —
  серверного рендера/экспорта нет. Headless-вызов из бота на VPS невозможен.
  Нужен другой инструмент монтажа (реалистичный вариант — ffmpeg у себя).
- **Управление только через Telegram-бота.** Ни веб-дашборда, ни внешней CRM
  (29.08: уточнено — раньше здесь стояло «бот + CRM», от CRM отказались полностью).
- TikTok/YouTube/VK — вне объёма. Код (`blotato_service.py`, платформы в enum) удалён
  21.08, не заглушка на будущее.
- Фото/карусели/сторис генерируются и утверждаются, но автопостинг у них не запускается.

## Что нужно от пользователя

**Обязательные (без них `config.py` падает при импорте):** `TELEGRAM_BOT_TOKEN`,
`ANTHROPIC_API_KEY`, `DATABASE_URL`, `VAULT_ENCRYPTION_KEY` (генерируется через
`Fernet.generate_key()`, не покупается), `GOOGLE_SERVICE_ACCOUNT_JSON`.

**Для прода:** `REDIS_URL`, `POSTGRES_PASSWORD`, `GOOGLE_DRIVE_ROOT_FOLDER_ID`.

**По мере подключения:**
- `ELEVENLABS_API_KEY` — обычный REST API, ключ в личном кабинете. Проблем нет.
- `HIGGSFIELD_API_KEY` — API есть (`docs.higgsfield.ai`), но авторизация из **двух** значений:
  `Key <API_KEY_ID>:<API_KEY_SECRET>`. В `config.py` поле одно — при реализации адаптера
  нужно будет разнести на два.
- `VYRA_MCP_URL` — **ключа не существует**, см. раздел договорённостей. Поле в конфиге
  пока мёртвое.
- Уникализация — см. отдельный раздел ниже, ключа нет, нужен Telegram-юзербот.

**На каждый IG-аккаунт** (в зашифрованную таблицу `credentials`, не в `.env`):
логин, пароль, TOTP-секрет, **свой резидентный прокси** — общий IP на 20 аккаунтов
даёт массовый бан.

## Уникализация видео (шаг `uniquify`, папка `16_уникализировано`)

**Зачем:** Instagram матчит видео по перцептивному отпечатку. Один и тот же рилс на
нескольких аккаунтах фермы или перезалив удачного ролика → площадка распознаёт дубль,
режет охваты или не пропускает публикацию. Уникализация меняет отпечаток техническими
правками: обрезка кадра, лёгкий цветокор, шум, метаданные, иногда зеркало и скорость.

**Место в пайплайне:** финальный шаг, после монтажа, прямо перед публикацией.

**Решено: делаем локально через ffmpeg** — `services/uniquify_service.py`.
Отказались от `@unikalizator_videobot`, потому что наш бот написать ему **не может**:
с 07.05.2026 Telegram разрешил bot-to-bot, но только при взаимном opt-in, а чужую сторону
мы не контролируем. Путь через него требовал бы юзербота на Telethon с реальным номером
телефона плюс зависимости от чужого сервиса.

**Как устроен модуль:** параметры детерминированы от `(account_id, variant)` — у каждого
аккаунта свой стабильный «почерк», повторный прогон даёт тот же результат. Правки мелкие
и незаметные глазу: обрезка 1–3.5% с обратным масштабированием (геометрия Reels
сохраняется), яркость/контраст/насыщенность/оттенок, шум, скорость 0.97–1.03 с
`atempo` для питча, полная зачистка метаданных.

`mirror` по умолчанию **выключен** — зеркало разворачивает вшитые субтитры и логотип.
Включать только для роликов без текста в кадре.

Проверить отдельно, без бота:
```bash
python -m services.uniquify_service in.mp4 out.mp4 --account 3
```

**Цепь собрана и подключена** (`handlers/media.py` + `services/library.py`):
приём видео → ffmpeg → номер по порядку → Drive `16_уникализировано` → `ContentItem`
→ файл обратно в чат. `media.router` регистрируется **до** `scenarios.router`, иначе
его catch-all `F.text` съедает триггер.

Известное ограничение: Telegram отдаёт ботам файлы **до 20 МБ**. Для роликов тяжелее
нужен другой путь (Drive напрямую) — пока просто сообщаем об этом.

Известный edge case: `run_uniquify` не фильтрует состояние, поэтому слово «уникализ…»
посреди интервью персонажа перехватит диалог вместо того, чтобы стать ответом.

**Честная оговорка:** не гарантия. Снижение риска, а не защита — детект у Instagram
сложнее файлового хэша.

## Слой генерации

Три модуля, разделённые по ответственности:

**`services/persona.py` — карточка персонажа.** Структура вместо прежней склейки
вопросов-ответов в одну строку. Ключевое поле — `appearance_lock`: описание внешности,
которое **дословно** подставляется в каждый промпт генерации изображения. Именно
дословное переиспользование, а не пересказ, держит лицо AI-блогерши одинаковым от кадра
к кадру. Меняешь lock — это уже другой человек.

Интервью на создании аккаунта: `PERSONA_INTERVIEW` (15 вопросов, для блогерш) и
`BRAND_INTERVIEW` (10, для брендов — без внешности). Карточка лежит в `Account.persona_json`.

**`services/prompts.py` — брифы по сценариям.** У каждого сценария свой `Brief` с четырьмя
полями: задача, жёсткие ограничения площадки, типичная ошибка именно в этой задаче,
критерий готовности. Раньше на всё был один общий промпт — bio и сценарий рилса писались
одинаково, и получалось безлико.

**Это данные, а не код.** Настройка качества = правка текста брифов. Заводить новый
сценарий — добавить `Brief` и триггер, трогать логику не нужно.

**`services/claude_service.py` — вызов модели.** `generate_variants` возвращает
нумерованные варианты через structured output (`output_config.format`), а не парсит их
из прозы. Каждый вариант несёт `angle` — чем он отличается, чтобы выбор был осмысленным.
При ❌ в модель уходит и замечание, и отклонённый текст: без второго она не знает,
от чего отталкиваться.

Модель — `claude-opus-5` с adaptive thinking.

## Проверка ключей и сервисов

```bash
python scripts/healthcheck.py
```

Проверяет всё разом: Anthropic, Telegram, Postgres, Redis, Vault, Google Drive,
ElevenLabs, Higgsfield, HikerAPI — ключ на месте, отвечает ли сервис, что с подпиской
и остатком квоты. Отсутствующий ключ даёт `SKIP`, а не падение, так что запускать можно
на любой стадии настройки. Флаг `--json` — машиночитаемый вывод.

Намеренно **не** импортирует `config.py`: тот требует все секреты при импорте, и одного
недостающего хватило бы, чтобы уронить всю проверку.

Не покрывается: Vyra (авторизация только в браузере) и логин IG-аккаунтов
(дёргать нельзя — триггерит защиту Instagram).

## Риск, о котором помним

Публикация идёт через приватный API Instagram — это против правил платформы, и обойти нельзя:
официальный Graph API не умеет кликабельные ссылки в сторис. Блокировки будут; лимиты частоты
постинга в коде пока не реализованы.
